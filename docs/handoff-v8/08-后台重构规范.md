## 1. 目标与底线

1. **只有一位管理员**（产品负责人本人），大多数时候在手机上顺手处理，偶尔在电脑上查数据、对账。
2. **隐私底线不变**：后台不提供任何查看用户训练记录、体重、饮食、聊天或备注的功能。管理接口返回的数据中，除申请人自己填写的申请说明外，不得出现用户自由文本或健康数据，并用契约测试保证。
3. **要紧的事主动找人**：需要处理的事集中在"待办"里，并按第 5.6 节主动提醒，不靠管理员自己翻页面发现。
4. **每个操作都说清后果**：危险操作旁边直接写明会发生什么、不会发生什么；结果未知时明确提示，只允许"重试同一次"（复用请求编号），不得让管理员误以为已成功。
5. **每个管理操作都留痕**：写入操作记录，内容包括操作人（Access 身份）、时间、对象短 ID、操作类型、结果。

## 2. 布局：手机用口袋，桌面用值班台

同一套页面和数据，按宽度切换布局，不做两套应用。

| 宽度 | 布局 | 用途 |
|---|---|---|
| < 960px | **口袋**：单列卡片，一张卡片只处理一件事，底部导航"待办 / 用户 / 账本 / 更多" | 日常处理待办 |
| ≥ 960px | **值班台**：左侧深色导航（含待办计数），顶部五格系统状态，主区为"待办队列 + 图表"，下方为数据表 | 查数据、看图表、对账 |

- **待办数据只有一份**：手机上处理完，桌面端同步消失，反之亦然。
- **用户详情页**：用"流水"形式展示单个用户，桌面端三栏（用户列表 / 流水时间线 / 操作面板），手机端为单列（概要 → 操作卡片 → 流水）。流水只含资格、用量、费用和管理操作，不含训练内容。

### 2.1 视觉

后台使用独立的紧凑令牌，**不参与前台的四套主题切换**。品牌与前台青瓷一脉相承：

| 令牌 | 值 | 用途 |
|---|---|---|
| 底色 | `#EEF1EF`（桌面）/ 青瓷渐变 `#E6EEE9 → #DDE6E0`（手机） | 页面背景 |
| 面 | `#FFFFFF` / `#F2F5F1` | 卡片、表格 |
| 文字 | `#16201C`，次要 `#4F5F58` | — |
| 导航底 | `#16201C`，文字 `#DCE5E0` | 桌面左侧导航 |
| 主色 | `#3E6B5C`（主按钮）、`#1F5F4A`（链接、强调） | — |
| 状态 | 正常 `#2F7A55`，注意 `#9A6B12`，紧急 `#B3261E` | 状态格顶边、待办圆点、标签 |
| 金色 | `#C7A867` | 待核算预留 |
| 字体 | 正文 Noto Sans SC；数字 Archivo（桌面）/ Cormorant Garamond（手机大号金额） | 数字一律等宽数字 |
| 圆角 | 桌面卡片 14–16px、按钮 10px；手机主卡 28px、卡片 24px、按钮全圆 | — |

- 触控目标 ≥ 44px；手机主操作按钮 ≥ 52px。
- 状态不只靠颜色区分，同时有文字（如"需要核对""开启"）。
- 文字对比度 ≥ 4.5:1。
- 不使用前台的流光描边与呼吸背光；按压回弹可以沿用。
- 中文默认，支持英文切换。

## 3. 信息架构

| 入口 | 内容 |
|---|---|
| **待办**（首页） | 按紧急程度排序的待办卡片；桌面端附系统状态五格和近 7 天 AI 费用图 |
| **申请** | 申请列表与审核（批准 / 拒绝 / 免邀请码开通）、常用审核备注 |
| **用户** | 用户列表（按短 ID 或名称查找）→ 用户详情（流水 + 操作）、邀请码发放与作废、用户求助排查 |
| **账本** | 月预算、已用、待核算预留、按供应商账单核算、导出 |
| **芽芽** | AI 费用监控、评测报告、提示词版本 |
| **开关与发布** | 功能开关、发布与回滚 |
| **错误** | 错误监控 |
| **设置** | 运行配置、常用审核备注、维护公告、语言 |
| **操作记录** | 全部管理操作，可筛选 |

手机端底部导航只放"待办 / 用户 / 账本 / 更多"，其余入口在"更多"里。

## 4. 待办

### 4.1 待办来源与紧急程度

| 来源 | 紧急程度 | 卡片主操作 |
|---|---|---|
| 账本需要核对（新调用已暂停） | 紧急 | 逐笔核对 |
| 冒烟测试失败或生产错误突增 | 紧急 | 查看（可直接回滚） |
| 本月预算用到 100% | 紧急 | 查看费用 |
| 结果未知的管理操作（如额度恢复超时） | 注意 | 看流水 / 重试同一次 |
| 本月预算用到 80% | 注意 | 查看费用 |
| 敏感功能开关等待确认开启 | 注意 | 查看并确认 |
| 申请等待超过 48 小时 | 注意 | 逐个审核 |
| 新申请 | 普通 | 逐个审核 |
| 预算用到 50% | 普通（只提示，可关闭） | 查看费用 |

### 4.2 卡片规则

- 一张卡片 = 一件事：标题说清是什么，一句话说明影响，一个主操作。
- 不使用"失败""违规"之类的吓人措辞；说事实和影响，例如"9 月有 2 笔预留没对上供应商账单。核对完成前，所有新的 AI 调用都会暂停。"
- 待办在条件消失时自动移除；管理员不能手动关掉紧急待办。

## 5. 第一优先能力

### 5.1 功能开关管理

- 列出每个开关：名称、说明、预览环境状态、生产环境状态、是否敏感、最后修改人和时间。
- 敏感开关（涉及健康数据、外发、推送、AI 费用）在生产开启时，需按第 6.1 节二次验证，并显示影响说明。
- 任何开关都可以一键关闭，生效时间不超过 1 分钟，无需重新发布。
- 每次修改写入操作记录。

### 5.2 发布与回滚

- 显示当前生产版本、上一版本、发布时间、冒烟测试结果（逐项）。
- 一键回滚到上一版本（二次验证）；回滚后自动重跑冒烟测试，并在待办中报告结果。
- 回滚只切换代码版本，不回退数据库结构；所有迁移必须保证上一版本能读取当前数据（与"先加、再迁、后删"规则一致）。

### 5.3 AI 费用监控

- 按天、按任务（生成计划、今日调整、修改计划、回顾）统计调用次数和费用；桌面端显示近 7 天和本月图表，手机端显示本月合计和进度条。
- 区分"已核算费用"和"待核算预留"。
- 预算达到 50%、80%、100% 时进入待办（见第 4.1 节），80% 和 100% 同时主动提醒。
- 显示自动降级为本地规则的次数和时间段。

### 5.4 芽芽质量

- 评测报告：每次评测运行的时间、提示词版本、模型、各场景通过与否、话术检查违规条数、耗时与费用。评测只使用合成数据。
- 提示词版本：列出各任务的版本，显示当前生产使用的版本；可切换到其他已登记版本或回退（二次验证，写入操作记录）。
- 生产中话术检查拦截的次数（只统计次数和规则类别，不保存用户内容或模型原文）。

### 5.5 错误监控

- 按错误类型归组：次数、首次与最近出现时间、涉及版本、浏览器分布、趋势。
- 上报内容只允许：错误类型、页面路由、应用版本、浏览器与系统大类、时间。不得包含用户输入、健康数据、IP 或任何可识别用户的信息。
- 1 小时内某类错误次数超过过去 7 天同时段平均值 3 倍（且不少于 10 次）视为突增，进入待办并主动提醒。

### 5.6 主动提醒管理员

- 通道：推送到管理员手机（后台作为 PWA 安装，Web Push）。iOS 需要先把后台添加到主屏幕；设置页说明这一点并提供"发送测试提醒"。
- 触发：账本需要核对、冒烟测试失败、错误突增、预算 80% 和 100%、申请等待超过 48 小时（每天最多提醒一次）。
- 提醒内容只写事件和数量，不包含用户名称或申请内容。
- 管理员可以在设置中按类别关闭提醒；紧急类（账本、冒烟测试、预算 100%）不能关闭。
- 静默时段可设置，紧急类不受静默时段限制。

## 6. 第二优先能力

### 6.1 危险操作二次验证

- 适用：删除账号、重新生成激活码、修改运行配置、生产开启敏感开关、回滚、切换提示词版本、批量清理过期申请。
- 做法：检查 Cloudflare Access 令牌的签发时间，超过 5 分钟则要求重新登录后再执行；执行前展示后果说明并要求确认。
- 二次验证失败或取消，不执行任何改动。

### 6.2 运行配置在后台修改

- 可修改：额度默认值、月预算上限、单次预留、并发上限、申请保留天数。
- 环境变量作为初始默认值；后台修改后保存在数据库并带版本号，可查看修改历史并恢复到任一历史版本。
- 每项有合法范围校验；修改前展示"改前 → 改后"和影响说明；按第 6.1 节二次验证；写入操作记录。
- 修改只影响之后的请求，不追溯改写已有用量和费用。

### 6.3 对账与记录导出

- 账本（按月，含预留、已核算、未归属费用）和操作记录导出为 CSV（UTF-8 带 BOM，Excel 可直接打开）。
- 导出内容只含短 ID，不含申请说明等用户填写的文本。
- 导出本身写入操作记录。

### 6.4 用户求助排查

- 输入用户短 ID，查看最近 30 天的请求状态列表：时间、任务类型、结果（成功 / 超时 / 被预算拦截 / 被额度拦截 / 被话术检查拦截 / 供应商错误）、费用。
- 不显示请求和回复的内容。
- 每条状态旁给出管理员可以做的下一步（例如"恢复额度""重新生成激活码"）。

### 6.5 常用审核备注

- 在设置中维护常用语（批准备注、拒绝原因），审核时一键填入，仍可修改。
- 拒绝时备注必填的规则不变。

### 6.6 维护公告

- 管理员可以发布一条全站公告：内容、开始时间、结束时间（必填，最长 7 天）。
- 前台在页面顶部以一行说明显示，可关闭；不弹窗、不打断训练（训练中不显示）。
- 提供默认文案，例如"芽芽暂时休息，训练和记录不受影响。"；管理员自定义的文案同样经过话术禁用词检查。
- 同时只能有一条公告；发布与撤下写入操作记录。

## 7. 后端与数据

- 新增数据一律新增表或字段，遵循"先加、再迁、后删"；不得改写已有账本、用量和操作记录。
- 新增内容：功能开关及其历史、运行配置版本、提示词版本切换记录、错误事件聚合、费用按天按任务汇总、管理员推送订阅、维护公告、常用审核备注。
- 所有管理接口继续通过 Cloudflare Access 校验管理员身份；写操作带幂等请求编号。
- 费用、错误和评测数据由对应的业务线产出，后台线只负责管理接口和界面；两边以接口文档约定字段，变更按安全演进规则处理。

## 8. 明确不做

- 查看任何用户的训练、体重、饮食、聊天或备注内容。
- 多管理员与权限分级（以后用户多了再做）。
- 匿名统计看板、用户反馈收件箱（第三优先，暂不做）。
- 面向用户的营销推送。

## 9. 验收

- 手机 390 / 320 和桌面 1440 / 1024 截图：待办、申请审核、用户详情、账本、开关与发布、芽芽、错误、设置。
- 契约测试：所有管理接口的响应中不含训练数据和用户自由文本（申请说明除外）。
- 二次验证、结果未知的重试、配置历史恢复、回滚后冒烟测试，均有浏览器测试。
- 推送提醒：测试提醒可送达；紧急类不能关闭；静默时段生效。
- 对比度、触控尺寸、键盘操作、屏幕阅读器标签检查通过。
- 旧后台功能逐项对照，确认没有丢失（申请审核、免邀请码开通、邀请码发放与作废、激活码重发、额度恢复、删除账号、核算、清理过期申请、AI 开关、操作记录）。
