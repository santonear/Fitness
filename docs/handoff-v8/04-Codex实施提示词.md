### 6. 不可违反的约束

1. **不改业务安全边界**：AI 返回一律不能直接写数据，必须用户确认、版本校验通过后由应用执行；外发最小化；完成记录只读；备份与恢复失败不得部分覆盖。
2. **样式只能用设计变量**：页面与通用组件中不得出现十六进制颜色、`font-family`、具体字号、圆角、阴影值；`[data-theme=...]` 选择器只允许出现在 `src/themes/<id>/tokens.css`。
3. **主题差异只在 9 个签名组件里**（规范第 1 部分第 6 节）。需要新增签名组件，先提问。
4. **不新建按版本命名的 CSS 文件**；旧样式文件在第 3 阶段删除。
5. **主卡流光描边每屏最多一张**；训练中关闭所有持续动画；尊重 `prefers-reduced-motion`。
6. **训练中不倒计时、不自动开始下一组、不自动切换动作、不弹窗打断**。
7. **文案按规范逐字实现，中英双语**；规范列出的工程化表达不得出现在界面上。
8. **字体打包进应用并子集化**，不依赖 Google Fonts。
9. **不得删除或伪造用户数据**；迁移必须幂等、事务完整、失败不部分写入，并在至少 3 份真实旧备份上验证。
10. **应用内不设任何开发或评审入口**：AI 架构评审、契约示例、Prompt 结构、评测面板只存在于文档，不得出现在用户端、设置、调试开关、隐藏手势或 `/admin`，也不进入生产包（规范第 2 部分第 2 节）。现有代码里若有此类入口，在第 3 阶段删除。
11. 不确定时**提问**，不要猜。

### 7. 并行开发方式

为节约时间，按"接口先行、分波次并行"组织。下面第 0–5 阶段描述的是**工作内容**；实际执行顺序按本节的波次。

**原则**
1. 先冻结接口，再并行：第 0 波把各条线共用的类型、契约和目录定下来并合并，之后各条线只依赖这些接口，不互相等待实现。
2. 一条线 = 一个独立工作树 + 一个分支，从 `v8/integration` 拉出、PR 合回 `v8/integration`；`main` 只在第 3 波结束后合并一次。
3. 每条线只改自己"负责的文件"（见下表）。需要改别人负责的文件，在 PR 中提出，由负责的线修改。
4. PR 要小（单个 PR 原则上不超过约 600 行有效改动），每天至少同步一次 `v8/integration`。
5. 同时进行的线不超过 5 条。
6. 机械规则（设计变量、`[data-theme]`、禁用词、开发入口、类型检查、单元测试）全部由 CI 拦截，不依赖人工审查。

**第 0 波（串行，1 条线）：规范归位 + 接口冻结**
- 第 0 阶段的全部内容，另加：

### 10. 必须主动提问的情况

- 规范、令牌、原型三者冲突；
- 现有数据无法按迁移规则无损转换；
- 某个交互状态在规范和原型中都没有定义；
- 实现某条规范需要突破第 6 节任何约束；
- 并行开发中发现第 0 波冻结的接口需要修改；
- 发现规范可能带来安全、隐私或无障碍问题；
- 认为规范本身需要修改（先提问，确认后再改 `UIUX20261008.md`）。
