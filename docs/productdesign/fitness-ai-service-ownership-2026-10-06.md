# AI 服务供给与额度来源

版本：v1.0；日期：2026-10-06。

## 已确认产品规则

1. Fitness 后台统一调用模型供应商 API，并将结果呈现给 Fitness 用户。用户不需要购买 AI 订阅、绑定 AI 供应商账号或提供 API 密钥。
2. 模型 API 凭据属于 Fitness 的服务端项目配置；供应商配额、用量及费用由项目管理。继续保留邀请码、个人次数、全局预算、并发预留、请求去重及待核算状态。
3. 不采用用户 ChatGPT 订阅授权；不将维护者个人 ChatGPT 订阅作为其他 Fitness 用户的公共调用额度。
4. 当前供应商路线为 Gemini API。免费项目可用于限定测试，但不据此承诺永久免费或生产容量已经通过。正式供应商参数、费用与发布继续按既有门禁评审。
5. 密钥仅保存在服务端安全配置，不进入前端、训练 JSON 或公开仓库。浏览器本地训练保存规则不变；模型外发仍须逐次确认，D1及日志不保存训练、目标、备注或 AI 结果正文。

## 与订阅方案的区别

普通 OpenAI API Key 使用独立的 API 计费。Sign in with ChatGPT 的订阅使用能力是另一种 OAuth 授权路线，要求调用服务于被授权的同一用户；不是维护者订阅向全站用户提供额度。本项目不纳入该路线。

依据：
- https://learn.chatgpt.com/docs/auth
- https://openai.com/policies/sign-in-with-chatgpt-terms/

## 有效候选与待核算费用（当前产品规则）

有效候选允许在费用未知时先交付，用户可查看、编辑并明确保存到本地。费用显示待核算，完整预算预留、个人次数和请求去重继续保留；核算前阻止新的模型请求。理解结果返回后的计划生成同样受该限制，不能以候选已交付推断费用已结清。

无效候选、供应商失败或非法费用不显示成功，不按零费用释放预留。取消不保证撤回已发送请求或免计费；本地保存、回滚不回滚供应商费用。已有候选在资格查询失败或到期时不因这些状态被删除，保存仍遵循日期冲突、恢复代次及既有本地保护。

此规则替代此前“候选先交付仍待决定”的状态。当前进入本地实现与验证，正式站点 AI 继续关闭；生产启用及资源变更另行评审。
