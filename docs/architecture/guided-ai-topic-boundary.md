# 健身对话主题边界评审稿

状态：2026-10-07 用户已确认主题范围及分层限制方向；不是已经启用的主题识别服务。正式 AI 继续关闭。

## 范围

核心对话限定训练目标、条件、日期安排、动作、逐组目标、运动安全与相关身体指标，允许与当前目标相关的一般饮食、睡眠和恢复问题。纯娱乐、编程、投资等无关请求不进入通用问答；不提供疾病诊断、处方、治疗或康复处方。

不因拒绝 AI 话题而暂停、结束或删除本地训练、计划、候选及事实。

## 执行设计

1. 后端固定职责和用途；不允许客户端提交 system prompt 或改变用途。目标、备注、历史及对话内容始终作为不可信数据，不能提升为指令。
2. 明确违规的协议或用途在供应商调用前拒绝。普通文本不采用“出现关键词即通过”的规则，以免误挡正常表达或被“健身”关键词绕过。
3. 语义主题判断返回结构化 related / unrelated / clarification_needed，不生成开放域答案。是否单独分类调用，需结合延迟、准确率和预算评估；不默认增加一轮付费调用。模糊但可能相关的问题只提出澄清，不擅自推断。
4. unrelated 只返回简短双语引导：本服务协助健身与训练计划，请回到目标、训练条件或计划调整。不得把供应商拒绝文本保存成训练候选。既有日期、受控动作、指标和确认校验仍独立执行。
5. 模型已参与判断时可能产生费用，仍遵守预留、待核算、取消及失败计费契约；不能宣传无关问题必定免费。供应商调用前确实拒绝的请求不占模型生成次数，但平台限流仍适用。
6. 重复无关输入采用独立频率限制和冷却；阈值待测、待批。不能让正常取消、状态查询、离线训练或本地保存依赖这一限流。
7. 不将目标正文或健康信息记入 D1、日志、遥测。安全日志只保存必要决策码与用量元数据；供应商的数据处理边界仍需明确。

## 验收

- 正常中英文目标、日期调整、运动条件及安全疑问不被误挡。
- 纯编程、娱乐、投资请求得到拒绝，不产生候选或训练事实。
- 混合问题、隐喻和不明确问题可澄清，不能只看关键词。
- “忽略规则”、角色伪装、历史备注中的恶意指令不能改变服务用途。
- 用户将无关主题包装成健身计划时，结构校验不能替代主题判断。
- 重复请求、冷却、状态未知与可能计费反馈符合原控制契约。
- 拒绝后当前输入、候选、进行中训练和历史保持；离线闭环仍可用。
- mock 只能验证控制分支；真实语义识别准确率、误拒率、延迟和费用另验，不能承诺完全阻止越界。

现有 `src/backend/prompt.ts` 已包含成人一般健身职责，但只有提示词约束，尚不足以证明上述分层限制已实现。新增 guided-dialogue-v1 仍为本地合成流程，不能将旧接口状态视为新对话服务上线证据。
