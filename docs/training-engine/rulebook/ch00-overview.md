# 第 0 章　手册说明

版本：v0.1（2026-10-14）　｜　机器可读镜像：`rules-ch00.yaml`（仅 `meta.*` 条目）

## 0.1 这本手册是做什么的

本手册把训练科学证据转成两种形式：

1. **中文章节**（本目录下的 `chXX-*.md`）——给产品负责人、教练和运动科学顾问审核阅读，说明每条规则“定了什么、为什么、证据有多硬”。
2. **机器规则**（`rules-chXX.yaml`）——给确定性训练引擎（deterministic training engine）直接读取。引擎不做自由发挥：同样的输入永远得到同样的计划。

两者必须一一对应：手册里每条规则前都写着规则 id（加粗方括号写法，如 `[safety.screen.parq]`），YAML 中有同名条目。改其中一处，必须同时改另一处。

## 0.2 适用人群

- **主体人群：** 18 岁及以上、健康的普通健身用户，在家或健身房训练。
- **专项模块：** 老年人（65 岁及以上）、孕期、产后，以及关节注意（膝 / 腰 / 肩 / 腕）。这些模块在对应章节中定义，只会让规则**更保守**，不会放宽主体规则。
- **未满 18 岁：** 不在适用范围内，引擎不为其生成训练计划（见 `safety.scope.age_min`，第 1 章）。

## 0.3 应用的边界：不诊断、不治疗、不做康复

本应用是健身工具，不是医疗器械。引擎和文案只允许做三件事：

| 允许 | 举例 |
|---|---|
| 保守调整训练 | 降低强度上限、减少容量、关闭跳跃类动作 |
| 动作替换 | 膝注意时把深蹲换成箱式蹲或臀桥 |
| 提示停止并寻求专业帮助 | 出现胸痛、晕厥等警示症状时结束训练并给出求助文案 |

明确禁止：

- 判断用户“有没有病”、解读症状的原因、给出诊断性措辞；
- 根据药物调整处方，或告诉用户某个负荷“对你的骨质疏松是安全的”；
- 宣称应用已“批准”或“放行”用户运动——医学许可只能来自医生或合格的运动专业人员，应用只记录用户自己确认的结果；
- 提供康复方案或“治疗某处疼痛”的训练。

证据库之间有分歧时，取**更保守**的选项，并在规则里写明取舍。

## 0.4 证据等级

| 等级 | 含义 | 手册中的写法 |
|---|---|---|
| **A** | 权威指南或立场声明（WHO、美国身体活动指南 PAG、英国首席医疗官 UK CMO、ACSM、NSCA、ACOG、PAR-Q+ 等） | 证据等级：A |
| **B** | 系统综述、荟萃分析（meta-analysis）或大型合并队列分析 | 证据等级：B |
| **C** | 从业者共识、单项研究，或**本产品的保守工程选择** | 证据等级：C；凡是工程选择，必须写明“工程选择”；证据库未覆盖而引擎又必须有的默认值，写“工程选择，待教练审核” |

补充约定：

- 证据只支持方向、不支持具体数字时，数字按 C 处理，即使方向本身有 A/B 证据。
- 证据库中标为 [unverified] 或来自二手来源的内容，在来源标签后加“（待核实）”。上线前应以原文核对。
- 不编造证据库里没有的数字。

## 0.5 引用标签

格式：`E0x:<证据文件中的标签或作者年份>`。证据库共 5 个文件：

| 编号 | 文件 | 主题 |
|---|---|---|
| E01 | `01-guidelines-safety.md` | 全球身体活动指南、运动前筛查与安全、减脂与步数、有氧强度与 HIIT |
| E02 | `02-resistance-dose.md` | 抗阻训练剂量：容量、频率、负荷、离力竭次数、组间休息、时长模型 |
| E03 | `03-program-design.md` | 课程设计：目标、分化、单次课结构、动作选择与顺序 |
| E04 | `04-progression-practice.md` | 进阶、减量、动作分类与难度 |
| E05 | `05-special-populations.md` | 老年人、孕期、产后、关节注意替换、需医学许可的情况 |

例：`E01:WHO20`、`E02:Currier2026`、`E03:Ribeiro-2021`、`E05:Riebe2015`。每章末尾列出本章用到的全部来源（完整书目 + 待核实标记）。

## 0.6 规则 id 命名规则

**[meta.id.convention]**

- **规则：** id 由三段组成：`领域.主题.名称`，全部小写英文，单词之间用下划线，段与段之间用点，例如 `dose.sets_week.beginner`、`safety.screen.parq`、`duration.set.work_time`；至少 3 段，最多 4 段；全手册唯一，一经发布不改名（废弃时在 YAML 中保留并加 `deprecated: true`）。
- **理由：** 引擎、日志和审核记录都用 id 引用规则；稳定、可读的 id 让“哪条规则导致了这个计划”可以追溯。
- **证据等级：** C（工程选择）
- **来源：** 本手册撰写规范（内部）

**常用领域前缀（登记表）：**

| 前缀 | 用于 |
|---|---|
| `meta` | 手册自身的约定 |
| `safety` | 筛查、医学许可、强度解锁、停止症状、复筛 |
| `dose` / `volume` / `progression` / `ladder` / `deload` | 抗阻剂量、进阶与减量 |
| `caution` / `pain` / `substitution` | 关节注意、疼痛规则、动作替换 |
| `older` / `pregnancy` / `postpartum` | 专项人群模块 |
| `aerobic` / `hiit` / `steps` / `fatloss` / `sedentary` | 有氧、间歇训练、步数、减脂、久坐 |
| `duration` | 时长估算与拟合 |

新领域前缀需在本表登记后再使用。

## 0.7 YAML 规则格式速览

每条规则一个条目，字段如下（完整规范见撰写规范）：

```yaml
- id: safety.screen.parq          # 领域.主题.名称
  chapter: 1
  type: gate                      # limit | default | gate | exclude | substitute | formula | template | copy | trigger
  applies:                        # 省略 = 全体
    population: [general, older_adult, pregnant, postpartum]
    level: [beginner, intermediate]
    goal: [health, fat_loss, strength, muscle, mobility, start_moving]
    caution: [knee, back, shoulder, wrist]
  value: { ... }                  # 数值写数字，枚举写英文
  evidence: A
  sources: [E01:PARQ23]
  note: 中文，≤60 字
```

- `type: copy` 的条目必须同时有 `zh` 与 `en` 两个文案字段。
- 动作相关的枚举（动作模式、`flags`、`joint_load` 键名、`position`、`impact`、`noise`、`space`、`use`）一律使用《动作标注标准 v0.1》（`annotation-rubric.md`）的写法；另新增动作模式 `balance`（单腿站立、平衡步行等）。
- 规则冲突时：安全类（`safety.*`、人群模块、关节注意）优先于剂量与时长类；同类规则之间取更严格者。

**[meta.conflict.precedence]**

- **规则：** 多条规则同时作用于同一参数时，按以下顺序决定：① `safety.*` 门槛与停止规则 → ② 人群模块（`older` / `pregnancy` / `postpartum`）→ ③ 关节注意与疼痛规则 → ④ 剂量、进阶、有氧目标 → ⑤ 时长拟合（`duration.*`）；同一层级内取更保守的值。时长拟合永远不能突破前四层设定的上限或下限。
- **理由：** 时间不够时，宁可少练也不能为了“塞进去”而放宽安全边界。
- **证据等级：** C（工程选择）
- **来源：** 本手册撰写规范（内部）

## 0.8 如何更新本手册

1. **触发更新的情况：** 新的权威指南或立场声明发布（例如 PAG 第 3 版预计不早于 2028 年）；证据库中“待核实”条目完成核实；教练审核或线上数据发现规则不合理；新增人群模块或动作库字段。
2. **流程：** 先更新证据库对应文件 → 修改章节与 YAML（同一个提交）→ 运行 YAML 校验（可解析、id 唯一、每条都有 `evidence` 与 `sources`）→ 教练 / 运动科学顾问审核 → 在下方版本记录表登记。
3. **版本号：** 只改措辞或来源标注，升第三位（v0.1.1）；改了任何数值、门槛或新增 / 删除规则，升第二位（v0.2）；结构性重写升第一位。
4. **向后兼容：** 规则 id 不改名；引擎在计划记录中保存所用手册版本号，便于追溯。

**[meta.manual.version]**

- **规则：** 当前手册版本为 v0.1，发布日期 2026-10-14；引擎生成的每份计划都记录 `rulebook_version`。
- **理由：** 规则会随证据更新，计划必须能追溯到生成它的规则版本。
- **证据等级：** C（工程选择）
- **来源：** 本手册撰写规范（内部）
