# AI 候选交付与核算工具

## 目标与边界

有效候选在费用未知时仍可交付、编辑和明确保存到本地。费用标记待核算，保留完整预算预留、次数占用和请求去重；核算前拒绝新模型请求。不将 token 估算视为实际账单，不持久化目标、训练或候选正文。

本地实现与隔离合成验证；本轮不启用正式站点 AI、不创建资源、不调用真实模型。真机验证继续暂缓。单次日期上限保持 1。

实现基线：61c91c99b0610281e07c3277037ec26a6bb4050a。

## 公共契约和所有权

成功响应包含 requestId、result、context（restoreGeneration、inputDigest 对应发送确认）及 accounting（settled 或 pending）。客户端验证后才接收。缺失费用且候选合法可返回 pending；非法费用、失败或无效候选不得伪装为有效结果。已知费用的既有结算规则保留。

- 后端交付：control.ts 与后端回归。
- 客户端和界面：client.ts、workflow.ts、status-feedback.ts、AiPage.tsx 与相关测试。
- 管理工具：新增 admin-report.ts、control-admin.mjs 与专用测试和使用说明。
- 公共接口与整合：http.ts、SDD、设计记录、综合验证由技术统筹负责；其他任务不改这些文件。

## 交付顺序和验收

1. 后端与客户端按同一响应契约并行实现；管理报告只读取控制元数据。
2. 整合受保护管理报告接口；核对鉴权、origin、无正文/凭据泄漏及失败不重试。
3. 单元测试覆盖 pending 交付、预算和次数保留、取消、无效输出、重复请求、人工结算和账本恢复；客户端覆盖契约、双语提示、未知状态及本地保存。
4. 类型检查、构建、受影响 Chromium/WebKit 回归和默认关闭入口 dry-run；针对性独立审查后记录证据。

核算前理解结果可以确认，但后续生成仍须等待负责人依据账单核算。候选本地保存不回滚已经发生的供应商费用。
