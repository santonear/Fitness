# Fitness 主题系统规范 v1

日期：2026-10-09
适用：用户端全部页面（后台 `/admin` 暂不纳入，见第 8 节）
视觉参照：画布「Fitness 视觉方向」中的 壹 留白、贰 静奢、叁 青瓷 共 9 屏效果图

> 目标：三套主题在应用内可切换；以后新增模板只需新建一个主题文件夹并注册，**不改任何页面代码**。

---

## 1. 原则

1. **结构一致，气质不同。** 三个主题共享同一套页面、信息架构、交互流程和文案。主题只改变"看起来和感觉起来"的部分。
2. **页面只认语义令牌和签名组件。** 页面代码里不得出现具体颜色值、字体名，也不得出现 `[data-theme="..."]` 这类按主题分支的选择器。
3. **差异集中在少数签名组件。** 主题之间超出令牌的差异（竖排标题、涟漪、超大细数字等），只允许出现在第 4 节列出的 7 个签名组件里。
4. **主题是一个文件夹。** 新增、删除、修改主题，只动 `src/themes/<id>/` 和注册表一行。

> 和现有 Atlas / Serene / Orbit 的区别：旧版式是在页面 CSS 里按主题覆盖颜色，所以每加一套都要改所有页面，而且只能换色。新体系把差异收进令牌和签名组件，主题之间可以有真正不同的气质，页面代码保持不变。

---

## 2. 目录与注册

```
src/themes/
  contract.ts          # 令牌名单、签名组件接口、ThemeManifest 类型
  registry.ts          # 已注册主题列表（唯一入口）
  ThemeProvider.tsx    # 读取偏好、应用令牌、提供签名组件
  qingci/              # 叁 青瓷（默认）
    manifest.ts
    tokens.css
    slots/             # 本主题的签名组件实现
    preview.webp       # 外观页缩略图，360×480
  liubai/              # 壹 留白
  jingshe/             # 贰 静奢
```

`manifest.ts`：

```ts
export const manifest: ThemeManifest = {
  id: 'qingci',                    // 小写字母，唯一，持久化用
  version: 1,
  name: { zh: '青瓷', en: 'Celadon' },
  tagline: { zh: '涟漪与呼吸，温润安静', en: 'Ripples and breath' },
  colorScheme: 'light',            // light | dark，用于系统栏、表单控件
  fonts: [/* 见第 6 节 */],
  slots: { /* 7 个签名组件，可只覆盖部分，其余用 base 实现 */ },
  preview: new URL('./preview.webp', import.meta.url).href,
};
```

`registry.ts`：

```ts
export const themes = [qingci, liubai, jingshe] as const;
export const defaultThemeId = 'qingci';
```

新增模板 = 新建文件夹 + 在 `themes` 数组里加一项。

## 3. 语义令牌（每个主题必须全部定义）

令牌以 CSS 自定义属性写在 `tokens.css` 的 `:root[data-theme="<id>"]` 下。**这是全仓库唯一允许出现主题选择器的地方。**

| `--c-ink` | 正文、标题 | `#1C201E` 墨 | `#EDE8DF` 骨白 | `#1E2B26` 墨绿 |

## 4. 签名组件（7 个，主题差异只允许出现在这里）

每个签名组件在 `contract.ts` 中定义统一的 props；`base` 提供默认实现，主题可以覆盖。页面通过 `useThemeSlot('StartAction')` 取用。

| 组件 | 职责与 props | 壹 留白 | 贰 静奢 | 叁 青瓷 |
|---|---|---|---|---|
| `BrandMark` | 芽芽的形象；`size` | 朱红方印"芽" | 文字"芽芽" | 涟漪中心的芽 |
| `PageTitle` | 页面主标题；`text` | 宋体竖排，右上 | 细黑横排 | 宋体横排 |
| `Suggestions` | 芽芽的建议回答；`items`、`onPick` | 下划线文字列表 | 发丝线行 + 香槟点 | 瓷白胶囊 |
| `WeekProgress` | 本周安排与完成；`days` | 墨线山脊 + 朱点 | 刻度线 | 涟漪点 |
| `StartAction` | 开始训练；`minutes`、`onStart` | 墨色矩形"开始" | 超大细数字 + 香槟胶囊 | 涟漪圆按钮 |
| `SetValue` | 本组重量 × 次数，默认带入计划值，点按修改；`weight`、`reps`、`onEdit` | 细黑数字 | 极细几何数字 | 衬线数字 |
| `RestClock` | 组间已歇时长，**正计时、不打断**；`elapsed` | 墨点 + 文字 | 细线 + 文字 | 小涟漪 + 文字 |

签名组件以外的通用组件（按钮、输入框、列表行、底部导航、弹层……）只有一份实现，全部由令牌驱动。

> 画布中 壹/贰 的"训练中"和 叁 的"组间休息"仍是旧交互（加减按钮、倒计时），实现时以「训练中：自主节奏」一屏和下面 4.1 节为准，只沿用各主题的视觉语言。

### 4.1 训练模式交互原则

训练时用户应该看着自己的身体，而不是看着手机。

1. **节奏由用户决定。** 不做休息倒计时，不自动开始下一组，不弹窗、不响铃打断。完成一组后只显示"已歇 1:12"的正计时，用户准备好了自己点"完成这一组"。
2. **顺序可以自由调整。** 计划里的动作顺序只是建议。屏幕下方列出今天其余动作，点一下就切换；器械被占时也不用跳过整个训练。
3. **一眼看懂，一下完成。** 每屏只有一个主操作，按钮高度不低于 72px，站在一臂之外也能看清和点中。
4. **默认值就是答案。** 重量和次数默认带入计划或上次的数值，大多数情况下只需点"完成这一组"；数值不同时才点数字修改，不放常驻的加减按钮。
5. **提醒是可选的，而且要轻。** 想要提醒的用户可以在设置里打开"休息到 X 秒时轻震一下"，默认关闭；以后可以接入锁屏小组件、手表或耳机语音，让用户不用拿起手机。
6. **屏幕常亮但安静。** 训练中保持屏幕常亮（Wake Lock），没有任何自动播放的动画；开启"减少动态效果"时全部改为静态。

## 5. 切换与持久化

- **默认主题：** 青瓷。新用户首次进入不选主题，不把它放进引导流程。
- **切换入口：** 设置 › 外观。展示每个主题的缩略图、名称和一句描述，点选后即时生效；正在进行的训练、草稿和当前页面保持不变（沿用现有行为）。
- **更多模板入口：** 外观页底部固定一行"更多模板"。现阶段进入后显示"新模板上线后会出现在这里"，列表由 `registry.ts` 自动生成，新增主题后不用改这一页。
- **持久化：** `localStorage` 键 `fitness-theme`，值为主题 `id`。读取失败或 id 不在注册表中时回退到默认主题。
- **旧偏好迁移：** 读到旧键 `fitness-appearance-v31`（atlas / serene / orbit）时，一律迁移到 `qingci` 并删除旧键。
- **应用方式：** `ThemeProvider` 设置 `<html data-theme="<id>">` 和 `<meta name="theme-color">`，按 `colorScheme` 设置 `color-scheme`。
- **系统深色模式：** v1 不自动跟随。以后可在外观页增加"跟随系统：浅色用 X，深色用 Y"。

## 6. 字体加载

- 应用以本地优先、可离线为前提，字体打包进应用，不依赖 Google Fonts。
- 中文宋体和黑体体积大，必须做子集化：常用 3500 字 + 应用内全部文案用字，按主题分包，只加载当前主题的字体。
- 切换主题时先显示系统回退字体（宋体回退 `"Songti SC", "STSong", "SimSun", serif`；黑体回退 `"PingFang SC", "Microsoft YaHei", sans-serif`），字体加载完成后替换，`font-display: swap`。
- 每个主题字体包压缩后建议不超过 1.5 MB；超过时在 PR 中说明。

## 7. 新增模板的检查清单（每个主题都要通过）

自动检查（写进测试，CI 必须通过）：

1. `tokens.css` 定义了第 3 节的全部令牌，没有多余令牌。
2. 正文对比度：`--c-ink`、`--c-ink-muted` 对 `--c-bg` 和 `--c-surface` 都 ≥ 4.5:1；`--c-on-primary` 对 `--c-primary` ≥ 4.5:1。
3. 页面目录（`src/ui/`）中没有十六进制颜色、`font-family`，也没有 `[data-theme` 选择器。
4. 截图测试：每个主题在 390px 和 1440px 下截取 初见、今日、训练中、设置›外观 四屏，与基准图对比。

人工检查：

5. 与画布效果图逐屏对比，构图、层级、留白偏离 3 处以上不算完成。
6. 触控目标 ≥ 44px；键盘焦点清晰可见；开启"减少动态效果"时涟漪、呼吸动画改为静态。
7. 中英文各看一遍，英文不溢出。

## 8. 实施顺序

1. **搭骨架：** `contract.ts`、`registry.ts`、`ThemeProvider`、`base` 签名组件；把现有 `AppearanceProvider` 替换为 `ThemeProvider`。
2. **先做青瓷：** 完成令牌和 7 个签名组件，按新信息架构改造 初见 → 今日 → 训练中 → 休息 四个关键流程。
3. **清理旧样式：** 删除 Atlas / Serene / Orbit 及按版本叠加的 CSS 文件，页面样式只保留"令牌 + 组件"两层。
4. **再加留白、静奢：** 只新增主题文件夹，不改页面；以此验证体系确实可扩展。
5. **外观页与"更多模板"入口。**
6. **后台 `/admin`：** 单独一套紧凑令牌，复用通用组件，不参与主题切换。

每一步单独提 PR，附 390px / 1440px 截图对比。

## 9. 给 Codex 的硬性约束（建议写入 AGENTS.md）

- 不得新建页面级 CSS 文件；新样式只能写在组件或主题文件夹里。
- 页面和通用组件里不得写死颜色、字体、字号、圆角、阴影，只能用令牌。
- 主题差异只能放在 7 个签名组件中；需要新增签名组件时，先在 PR 中说明理由，等设计确认。
- 任何 UI 改动必须附三个主题的截图。
