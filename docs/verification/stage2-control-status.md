# 后端资格与状态交互

## 行为

页面仍默认关闭。用户选择“连接后端”才请求同源 `/api/v1/trial/status`；不会在页面挂载时查询控制服务，也不会随查询发送目标、身体资料或历史。邀请码兑换复用现有同源 cookie 接口；无本地资格、余额或身份持久化。显式本地演示与真实接口模式分别提示。

查询失败不继续显示旧余次。次数表示占用，包含在途请求；服务端已有 pending 字段单独显示，缺字段为未知。无资格、到期、撤销、个人次数耗尽、项目预算、待核算和结果丢失提供有区别的反馈。项目预算不是个人欠费；取消不保证免计费。返回的候选与编辑内容不会因状态失败而删除，仍可按已有令牌规则明确保存到本地。

控制服务可用不等于模型启用。模型请求必须经过既有逐项确认、服务端资格及预算授权；本轮没有配置真实控制 Worker、D1 或供应商。静态站点返回 HTML 时显示状态未知，不伪造资格。

- 客户端及错误反馈针对性单元 7/7 通过；拒绝不可显示的到期时间、非法月份及私有服务端错误正文。
- Chromium/WebKit 双语控制及候选测试 22/22 通过，包括仅显式连接才请求、查询无正文、邀请码只发送代码、在途数量、模型关闭、到期清除旧状态、静态 HTML 回退、资格失效后保留候选并保存，以及个人次数/项目预算/待核算/结果丢失的请求反馈。
- 导航相关初轮与上述测试共 20/20 通过；键盘用例等待 SPA 导航就绪，保留五目的地完整断言。

环境：Windows，Playwright 1.63.0，Chromium 153 / WebKit 26.6。请求由本地路由模拟，无生产请求或真实模型调用。真机、实际资格 cookie 与云端控制事务不由这些测试证明。
