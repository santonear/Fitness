# 自动生成计划本地验证

日期：2026-10-07。基线：860b1b13de24d6dccb383eb76e0e6ec36b54d6df。分支：codex/trial-planning-entry。需求与数据边界见 ../architecture/automatic-planning-2026-10-07.md。

## 实现与针对性审查

有效试用入口、继续本地引导、资格自动刷新、单次发送、理解完成后的自动生成、七天内由 AI 选择日期、计划细节与最终采用已连接。原精确日期模式继续拒绝少日期、越界及重复；自动模式仅允许约定窗口的非空子集。供应商提示明确要求生成动作和训练量，并在备注给出休息与调整说明。

审查覆盖请求身份、取消/输入变化、资格未知、预算准入、身体/历史选择及本地采用。修复了仅本地保存的想法进入下一次目标摘要的问题。生成失败重试沿用原生成请求，避免重新理解或创建重复请求。最新计划采用后不会回退展示更早的未采用候选。采用仍经过本地服务的资料版本、恢复代次与日历冲突检查。

## 验证证据

- `npm run check`：类型、376 个单元测试与生产构建通过。
- 日期协议专项：新增跨年、用户时区、夏令时、非空子集、越界/重复与旧精确日期模式测试。新测试先因功能缺失失败，实现后与原协议及供应商适配共 23 项通过。
- 生产交互配置下，Chromium/WebKit 共 36 项不同 AI 浏览器用例有通过证据。最终全批次 32 项通过，4 项因结果区增加计划说明后测试选择器指向错误文字而失败；限定到动作备注后四项复跑通过。覆盖连续追问→自动生成→完整展示→采用、中文/英文、资格自动恢复、核算阻止生成、生成单独重试、请求身份不变、刷新后采用、输入变化阻止自动生成，以及本地想法不外发。
- 申请/资格/管理配置下，22 项 Chromium/WebKit 用例通过，包括有效资格→引导→重载继续→自动查询额度，及原有申请、发码、恢复额度和管理流程。
- 人工检查中英文窄屏截图。计划按日期、动作、组目标和备注展示，页面没有横向溢出。截图保留于本地 outputs/automatic-planning-en.png、outputs/automatic-planning-zh.png，不作为真实模型内容示例发布。
